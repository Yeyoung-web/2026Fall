## 사업 구상

- 이유: 식비 부담, 흩어진 동네 세일 정보, 필요한 양보다 큰 메뉴로 인한 주문 포기.
- 내용: 아끼기 = 이웃의 세일 제보 · 매장 직접 등록(할인·마감 상품 예약). 나누기 = 반 접시 주문(분할 주문).
- 계획: 2026년 11~12월 안암 제보 파일럿 → 2027년 상반기 매장 참여 → 수요 확인 후 나누기 파일럿.
- 절차: 제보·확인·방문·상태 갱신 → 매장 상품 등록·예약 → 매장 사전 허용·조건 공개 → 고객 요청·다른 고객 참여 → 수량 충족 → 매장 최종 수락 → 결제 확정·개별 준비와 제공.

## 구현과 제작

v9 모바일 웹 MVP는 요청·매칭·만료·결제 상태·테이블 연결을 시뮬레이션한다. 가장 복잡한 거래 흐름부터 기술 검증했고, 세일 제보 커뮤니티는 후속 개발 범위다. 실제 결제·배달·POS 및 상업 운영 실적과 구분한다.

모션그래픽의 구성: 01 왜 필요한가 → 02 하나의 목표 → 03-1 아끼기·이웃 세일 제보 → 03-2 아끼기·매장 직접 등록 → 04 나누기 → 05 안암 검증.

모션그래픽은 Python/Pillow의 프레임 애니메이션으로, AI 영화는 Google Flow / Veo 3.1 Lite 생성 동영상과 그래픽 합성으로 제작했다. 한국어 SunHi 내레이션과 자막을 적용했다. 영화는 미래 이용 시나리오다.

제작 소스는 source/, 영상 자막은 videos/에 있다. 음원 출처는 [BGM 크레딧](source/music-credit.md)에 기재했다. 원곡 및 분리 음악 WAV는 공개 배포에서 제외한다.

두 영상은 식비 부담과 과잉 주문의 불편에서 출발한다. 모션그래픽은 아끼기·나누기 두 방법을 설명하고, 영화는 나누기 경험에서 또 하나의 축인 아끼기를 소개하고, 세일 제보·방문 수요 확인·참여 매장의 오늘마감 등록을 거쳐 나누기를 더하는 단계적 확장을 설명한다.

## AI 협업 제작 과정

ChatGPT/Codex로 사업 기획과 MVP·영상 편집 코드를 구체화하고, 브라우저 연동·자동화로 Google Flow의 생성 작업을 수행했다. 제작 결과물과 과제 공지를 Claude에 함께 제시해 요구 사항·서사·가독성을 교차 검토한 뒤, 이예영이 개선 방향을 판단해 다시 제작에 반영했다.

사업 방향·대본 논리·가격과 수량·운영 순서·화면과 음향의 최종 선택은 제작자가 담당했다. AI를 단발성 생성보다 기획→구현→생성→검토→수정→검증의 연결 과정에 활용했다. 자세한 역할과 검토 기준은 보고서의 AI 협업 장에 정리했다.
